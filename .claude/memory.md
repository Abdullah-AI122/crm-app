# memory
Project: CRM frontend (Next.js App Router). Sibling API: ../backend.
Stack: next 16.2.10, react 19.2.4, TS 5, Tailwind v4 (@tailwindcss/postcss), HeroUI 3, @reduxjs/toolkit 2 + react-redux 9 (RTK Query), next-themes, framer-motion, recharts, lucide-react, react-icons, @react-oauth/google.
Scripts: dev=next dev, build=next build, start=next start, lint=eslint.
Env: NEXT_PUBLIC_API_URL, NEXT_PUBLIC_GOOGLE_CLIENT_ID. Read via config/env.js default export.
Routes: / , /login, /register, /Home, /auth/callback (OAuth landing: reads #token, GETs /auth/me, saves, replaces to /Home), /user/menage-profile, /developer (redirects to /developer/api-key), /developer/api-key, /workspace/[id], /workspace/[id]/module/[moduleId].
Empty dirs (no page.tsx): app/developer/data-console, app/user/apikey.
Developer section: app/developer/layout.tsx renders components/developerSidebar.tsx (nav: API Key, Data Console) + children; pages are content only. The API key UI lives at /developer/api-key (moved out of /user/menage-profile 2026-08-22); data via store/api/apiKey.api.ts (useGetApiKeyQuery/useGenerateApiKeyMutation).
Data layer: RTK Query only. store/baseApi.ts = single createApi (baseUrl from config/env.js, Bearer from lib/auth, tagTypes Workspace|Member|Module|Collection|Column|Record|RecordValue, keepUnusedDataFor 120s, refetchOnMountOrArgChange 60s). store/api/*.api.ts inject endpoints per resource; store/slices/ui.slice.ts holds activeWorkspaceId(+localStorage crm_active_workspace_id)/search/view; store/selectors/ + store/types.ts shared entity types; store/hooks.ts typed useAppDispatch/useAppSelector.
Board data: store/useModuleData.ts useModuleRecords(collectionIds) reads N getRecords/getRecordValues cache entries via a selector over state.api.queries (rules of hooks forbid per-collection hooks in the flat board) and drives fetches with endpoint.initiate.
Record->Collection ref is the field `collectionName` (ObjectId ref Collection) on both models/Record.ts and store/types.ts RecordItem — records have no `group`/`collection` field; always read it via getRecordCollectionId(). Moving a record between collections = PUT /records/:id with {collectionName: targetId, position}; updateRecord invalidates Record LIST-<source> + LIST-<target>, so passing a wrong/undefined source collectionId leaves the row in both lists (looks like a copy). Board sorts records by position client-side, so same-collection reorders apply optimistically without a refetch.
Board ordering: collections render sorted client-side by position (tie-break _id) in the module page, and createCollection now sends position: collections.length — the backend stores `position: position || 0`, so omitting it gave every collection position 0 and Mongo's .sort({position:1}) tie order decided the layout. createColumn has the same omission (columns still all land on position 0).
Optimistic writes: updateCollection/updateColumn/updateRecord/updateRecordValue patch the cache in onQueryStarted and roll back via patchResult.undo().
Tag convention: list ids are `LIST` (workspaces) or `LIST-<parentId>` (everything nested).
Auth storage: localStorage keys crm_auth_token, crm_auth_user (lib/auth.ts). Client-only guards on window.
Providers (layout order): store.provider.tsx (redux Provider + activeWorkspaceId hydration) > auth.provider.tsx GoogleOAuthProvider (popup SDK, unused by current flow) > theme.provider.tsx next-themes.
Google sign-in: components/ui/buttons/googleauth.tsx is self-contained (props mode|label|disabled|className|onError) — redirects to ${NEXT_PUBLIC_API_URL}/auth/google?mode=. Backend owns the secret; no client-side token exchange.
Components: components/ (Navbar, Sidebar, userSidebar, Avatar, Profile, searchBar, notifications, homesection) + components/ui/{buttons,cards,helpers,menu,modals}.
Static mocks: data/data.js only (palettes, notifications, column type options). The *.data.js fetch helpers were deleted.
Deleted 2026-08-22: lib/api.ts, lib/axios.ts, lib/mongodb.ts, context/WorkspaceContext.ts, data/{Workspaces,Modules,Members,Collections}.data.js. mongoose stays in package.json but is unused.
Constraint: Next 16 differs from training data — consult node_modules/next/dist/docs/ before writing framework code (AGENTS.md).
Theming: globals.css holds the whole contract — semantic tokens (--canvas/--panel/--card/--control/--foreground/--body/--muted/--hairline/--accent/--accent-hover/--primary) exposed via @theme inline as bg-canvas/bg-panel/bg-card/bg-control/text-foreground/text-muted/bg-accent, plus per-theme overrides of Tailwind's own --color-slate/gray/zinc-* so legacy utilities retheme without dark: variants. Theme class on <html> via next-themes (themes list comes from `themes` in data/data.js); <body> carries bg-canvas text-body so every route inherits. text-white and bg-black stay constant on purpose. New surfaces: token utility, never a hex. See LAYOUT.md §10/§12.
Cell value encodings (RecordValue.value is a string): timeline = JSON {startDate,endDate}; person/people = JSON array of USER ids (not member-row ids) parsed by parsePeopleValue(); rating = decimal string in 0.5 steps ("3.5"); checkbox = "true"/"false". Person/rating cells live in components/ui/helpers/{personCell,ratingCell}.tsx and are dispatched from the inline Cell in the module page (components/ui/helpers/columnCell.tsx is a stale unused copy). PersonCell needs a workspaceId prop (params.id) and reads the shared useGetMembersQuery cache entry.
